# Workshop Booking System

Учебный проект REST API для системы записи пользователей на мастер-классы.

## Стек

- Python 3.12
- Django 6.1
- Django REST Framework
- PostgreSQL 17
- Docker
- Docker Compose
- Postman

## Возможности

### Пользователь

- регистрация и авторизация;
- просмотр списка мастер-классов;
- просмотр информации о конкретном мастер-классе;
- просмотр информации об аудиториях;
- запись на мастер-класс;
- просмотр своих бронирований;
- отмена бронирования;
- повторная запись после отмены.

### Администратор

- создание мастер-классов;
- просмотр мастер-классов;
- редактирование мастер-классов;
- удаление мастер-классов;
- создание аудиторий;
- просмотр аудиторий;
- просмотр бронирований всех пользователей.

# Запуск проекта

## 1. Создать `.env`

В корне проекта необходимо создать файл `.env`:

    POSTGRES_DB=workshop
    POSTGRES_USER=dba
    POSTGRES_PASSWORD=sql
    POSTGRES_HOST=db
    POSTGRES_PORT=5432

Файл `.env` содержит параметры подключения к PostgreSQL и не должен добавляться в Git.

## 2. Запустить Docker

    docker compose up --build -d

После запуска:

- Django работает в контейнере `web`;
- PostgreSQL работает в контейнере `db`.

API доступно по адресу:

    http://localhost:8000/

Проверить состояние контейнеров:

    docker compose ps

## 3. Выполнить миграции

После первого запуска необходимо применить миграции:

    docker compose exec web python manage.py migrate

Проверить состояние миграций:

    docker compose exec web python manage.py showmigrations

Применённые миграции будут отмечены `[X]`.

Если PostgreSQL ещё не успел запуститься, необходимо подождать несколько секунд и повторить команду миграции.

# Создание администратора

Создать суперпользователя:

    docker compose exec web python manage.py createsuperuser

После создания необходимо установить пользователю роль `ADMIN`.

Открыть Django shell:

    docker compose exec web python manage.py shell

Выполнить:

    from users.models import User

    user = User.objects.get(username='admin')
    user.role = User.Role.ADMIN
    user.save()

Выйти из shell:

    exit()

В проекте используются две роли:

- `USER` — обычный пользователь;
- `ADMIN` — администратор.

Стандартный Django superuser не устанавливает автоматически значение `role=ADMIN`, поэтому роль задаётся отдельно.

# Работа с аудиториями

Перед созданием мастер-классов необходимо создать хотя бы одну аудиторию.

Аудитория содержит:

- название;
- адрес.

## Создать аудиторию

Только `ADMIN`.

    POST http://localhost:8000/api/workshops/classrooms/create/

Header:

    Authorization: Token <admin_token>

Body:

    {
        "name": "Аудитория 1",
        "address": "ул. Примерная, 1"
    }

Пример ответа:

    {
        "id": 1,
        "name": "Аудитория 1",
        "address": "ул. Примерная, 1"
    }

Полученный `id` аудитории используется при создании мастер-класса.

Например:

    classroom: 1

## Получить список аудиторий

    GET http://localhost:8000/api/workshops/classrooms/

Получение списка аудиторий доступно для просмотра.

Пример ответа:

    [
        {
            "id": 1,
            "name": "Аудитория 1",
            "address": "ул. Примерная, 1"
        }
    ]

# Авторизация

В проекте используется Token Authentication.

После авторизации полученный токен необходимо передавать в заголовке:

    Authorization: Token <token>

Также в настройках Django REST Framework включена Basic Authentication.

# Регистрация

    POST http://localhost:8000/api/auth/register/

Body:

    {
        "username": "testuser",
        "password": "Test12345!"

    POST http://localhost:8000/api/auth/login/

Body:

    {
        "username": "testuser",
        "password": "Test12345!"
    }

Пример ответа:

    {
        "token": "..."
    }

Полученный токен используется для авторизованных запросов:

    Authorization: Token <user_token>

Для получения токена администратора необходимо авторизоваться с учётными данными пользователя с ролью `ADMIN`.

# Мастер-классы

## Получить список мастер-классов

    GET http://localhost:8000/api/workshops/

Доступно без авторизации.

## Получить мастер-класс

    GET http://localhost:8000/api/workshops/1/

Доступно без авторизации.

В ответе возвращается информация о мастер-классе и связанной с ним аудитории.

Пример:

    {
        "id": 1,
        "title": "Основы Python",
        "descr": "Вводный практический воркшоп по Python",
        "date": "2026-10-20T18:00:00Z",
        "capacity": 15,
        "classroom": 1,
        "classroom_details": {
            "id": 1,
            "name": "Аудитория 1",
            "address": "ул. Примерная, 1"
        }
    }

Поле `classroom` содержит ID аудитории, а `classroom_details` — подробную информацию о ней.

## Создать мастер-класс

Только `ADMIN`.

    POST http://localhost:8000/api/workshops/create/

Header:

    Authorization: Token <admin_token>

Body:

    {
        "title": "Основы Python",
        "descr": "Вводный практический воркшоп по Python",
        "date": "2026-10-20T18:00:00Z",
        "capacity": 15,
        "classroom": 1
    }

Ожидаемый результат:

    201 Created

Перед созданием мастер-класса должна существовать аудитория с указанным ID.

## Изменить мастер-класс

Только `ADMIN`.

    PUT http://localhost:8000/api/workshops/1/

Header:

    Authorization: Token <admin_token>

Body:

    {
        "title": "Основы Python — обновлённый курс",
        "descr": "Новое описание воркшопа",
        "date": "2026-10-20T18:00:00Z",
        "capacity": 15,
        "classroom": 1
    }

Ожидаемый результат:

    200 OK

## Удалить мастер-класс

Только `ADMIN`.

    DELETE http://localhost:8000/api/workshops/1/

Header:

    Authorization: Token <admin_token>

Ожидаемый результат:

    204 No Content

# Тестовые мастер-классы

Для проверки бизнес-логики можно создать несколько мастер-классов с разными параметрами.

## Обычный мастер-класс

Используется для основной демонстрации API.

    {
        "title": "Основы Python",
        "descr": "Вводный практический воркшоп по Python",
        "date": "2026-10-20T18:00:00Z",
        "capacity": 15,
        "classroom": 1
    }

## Мастер-класс с одним свободным местом

Используется для проверки ограничения вместимости.

    {
        "title": "Тест вместимости",
        "descr": "Мастер-класс для проверки ограничения количества участников",
        "date": "2026-11-01T18:00:00Z",
        "capacity": 1,
        "classroom": 1
    }

После того как один пользователь успешно записался на этот мастер-класс, свободных мест больше нет.

Попытка второго пользователя записаться должна завершиться ошибкой:

    400 Bad Request

Сообщение:

    На мастер-классе нет свободных мест.

## Мастер-класс с прошедшей датой

Используется для проверки запрета бронирования прошедшего мастер-класса.

    {
        "title": "Прошедший мастер-класс",
        "descr": "Используется для проверки валидации даты",
        "date": "2025-01-01T18:00:00Z",
        "capacity": 15,
        "classroom": 1
    }

Создание такого мастер-класса администратором возможно.

Однако при попытке пользователя создать бронирование API возвращает ошибку:

    400 Bad Request

Сообщение:

    Нельзя записаться на прошедший мастер-класс.

Проверка даты выполняется при создании бронирования в `bookings/services.py`.

# Бронирования

## Создать бронирование

Только авторизованный пользователь.

    POST http://localhost:8000/api/bookings/create/

Header:

    Authorization: Token <user_token>

Body:

    {
        "workshop": 1
    }

При создании бронирования проверяется:

- мастер-класс ещё не прошёл;
- у пользователя нет активной записи на этот мастер-класс;
- есть свободные места.

Если все условия выполнены, создаётся активное бронирование.

## Повторная запись на один мастер-класс

Если пользователь уже имеет активную запись, повторный запрос:

    {
        "workshop": 1
    }

возвращает:

    400 Bad Request

Сообщение:

    Вы уже записаны на этот мастер-класс.

## Проверка ограничения вместимости

Для проверки используется мастер-класс с:

    "capacity": 1

Пользователь №1 создаёт бронирование:

    {
        "workshop": 2
    }

Результат:

    201 Created

После этого пользователь №2 пытается записаться на тот же мастер-класс:

    {
        "workshop": 2
    }

Результат:

    400 Bad Request

Сообщение:

    На мастер-классе нет свободных мест.

## Проверка прошедшей даты

Используется мастер-класс с прошедшей датой.

Запрос:

    POST http://localhost:8000/api/bookings/create/

Body:

    {
        "workshop": 3
    }

Результат:

    400 Bad Request

Сообщение:

    Нельзя записаться на прошедший мастер-класс.

## Получить бронирования

    GET http://localhost:8000/api/bookings/

Header:

    Authorization: Token <user_token>

Обычный пользователь получает только свои записи.

Администратор получает записи всех пользователей.

В ответе содержится информация о связанном мастер-классе и его аудитории.

Пример:

    {
        "id": 1,
        "user": 2,
        "workshop": 1,
        "workshop_details": {
            "id": 1,
            "title": "Основы Python",
            "descr": "Вводный практический воркшоп по Python",
            "date": "2026-10-20T18:00:00Z",
            "capacity": 15,
            "classroom": 1,
            "classroom_details": {
                "id": 1,
                "name": "Аудитория 1",
                "address": "ул. Примерная, 1"
            }
        },
        "status": "ACTIVE",
        "created_at": "2026-09-09T10:00:00Z"
    }

## Отменить бронирование

    DELETE http://localhost:8000/api/bookings/1/

Header:

    Authorization: Token <user_token>

Бронирование не удаляется из базы данных, а переводится в статус:

    CANCELLED

Это позволяет сохранять историю бронирований.

После отмены пользователь может снова записаться на тот же мастер-класс.

# Оптимизация

Для получения бронирований используется `select_related()`:

    Booking.objects.select_related(
        'user',
        'workshop',
        'workshop__classroom'
    )

Это позволяет сразу загрузить связанные объекты и уменьшить количество запросов к базе данных.

Для создания бронирования используются:

    transaction.atomic()

и:

    select_for_update()

`transaction.atomic()` объединяет операции создания бронирования в одну транзакцию.

`select_for_update()` блокирует выбранный мастер-класс на время выполнения транзакции. Это позволяет корректно обрабатывать одновременные попытки занять последнее свободное место.

# Postman

Для проверки API подготовлена Postman Collection.

Коллекция содержит запросы:

- регистрация;
- авторизация;
- получение мастер-классов;
- создание мастер-классов;
- изменение мастер-классов;
- удаление мастер-классов;
- создание аудиторий;
- получение аудиторий;
- создание бронирования;
- просмотр бронирований;
- отмена бронирования;
- проверка ошибок и ограничений.

Также добавлены автоматические проверки HTTP-ответов.

Пример проверки статус-кода:

    pm.test("Status code is 200", function () {
        pm.response.to.have.status(200);
    });

Пример проверки типа ответа:

    pm.test("Response is an array", function () {
        pm.expect(pm.response.json()).to.be.an("array");
    });

# Последовательность проверки проекта

Для воспроизведения проекта с чистой базы рекомендуется следующий порядок:

10. Создать обычный мастер-класс.
11. Проверить получение списка мастер-классов.
12. Проверить получение информации о мастер-классе вместе с данными аудитории.
13. Проверить создание бронирования.
14. Проверить просмотр своих бронирований.
15. Проверить повторную запись.
16. Создать мастер-класс с `capacity = 1` и проверить ограничение вместимости.
17. Создать мастер-класс с прошедшей датой и проверить запрет бронирования.
18. Проверить права доступа обычного пользователя.
19. Отменить бронирование.
20. Проверить повторную запись после отмены.
21. Проверить административные операции с мастер-классами.
22. Проверить создание и просмотр аудиторий.
